# Bento Product

Trigger: explicit Bento Grid, product-bento or Neo-Swiss bento request. Best for related capabilities with different evidence; not a universal page layout. Swiss principles stay shared. Apply the common contract in INDEX.md.

## Visual grammar

- Decide the story before card sizes: one leading benefit/evidence unit with supporting roles. A wide example, compact fact and image-supported explanation differ in size because their information differs, not to fill an arbitrary mosaic.
- Use installed Grid APIs for page rows/columns and UiCard for surfaces. Internal content may use normal flow/CSS. No masonry dependency, copied CSS container, invented row-span API or added gaps overflowing 12-column rows.
- Keep consistent gutters and a coherent shape vocabulary. Larger media and small metadata can vary in scale; comparable options/data retain clear alignment. Meaningful top offsets may add desktop rhythm, not compulsory stairs everywhere.
- Choose contrasting surface roles from the selected palette, not unrelated pastel tiles. Type hierarchy and image scale identify the main card before decoration.
- Each card earns its format through readable actual examples, specifications or explanation. No fake mini-dashboard/activity/chart. Informational cards need no action/lift; interactive cards need real destinations and keyboard/touch equivalents.
- On mobile preserve semantic order, remove offsets and let content set height. No clipped copy, forced equal heights or sideways mosaic hiding essentials. Use open sections elsewhere so the whole page is not boxes.
