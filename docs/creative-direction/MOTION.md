# Restrained native effects

Read when an effect is part of the brief. The application AGENTS.md and DESIGN.md remain binding; installed package technical contracts still apply. Effects support an already complete static composition; references do not authorize copying their engines or dependencies.

## Inspect ownership first

Search installed reveal, animation, media, partial-background and relevant component sources. Use existing behavior, props, slots and CSS variables first. `v-reveal` owns entrance effects; do not create another observer or split it into a competing reveal engine. `ViewPartialBackground` and some scrolling components already expose background/mask behavior: verify whether they fit the actual content. A short, site-specific decorative CSS treatment may be appropriate for a proven missing presentation, without recreating a package primitive or adding a global subsystem.

Choose one or two signature effects at most beyond ordinary control feedback. Keep the hero/LCP immediate, no slider by default, no custom scroll physics and no 3D animation without explicit request. Never introduce a preloader merely to stage an entrance. Select a few useful entrance groups, not v-reveal on every container by quota; relevant image-hover feedback remains required.

## State feedback and timing

A transition explains an actual change. Use existing package state/keyboard/focus APIs; do not rebuild controls or import the reference's React/motion stack. A small shared timing scale can start near 100–150ms for immediate feedback, 200–300ms for compact state changes and 300–500ms for larger transitions. These are contextual starting ranges, not delays imposed on a finished action. Keep established component timing unless a supported adjustment is justified. Choose easing for the task; bouncing/spring effects are not a universal default.

Show pending promptly; confirm success from the operation, not its animation. Reserve loading space with UiSkeleton where suitable. Progress percentages require actual progress; otherwise use honest indeterminate status. Reuse UiButton loading/disabled and existing alerts/toasts as supported, retaining accessible names and useful focus. Prevent duplicate mutations for the pending action without freezing unrelated controls. Keep actionable failures near their cause; transient notification is not the only error explanation.

Distinguish press feedback from commitment: an existing control may acknowledge pointer-down immediately while activation remains its normal click/release or keyboard contract. Do not submit, navigate or perform a destructive action on pointer-down to seem faster. Releasing outside/cancelling should follow the primitive's behavior. A visual transition must not block correction, a meaningful undo or normal dismissal. In gesture-capable installed components, check grab continuity, reversal and return focus; don't implement a spring/velocity/drag engine or extra hysteresis to imitate a platform. Preserve native page scroll and ordinary alternatives.

Transitions must reverse/end coherently under rapid toggles, repeated activation, Escape and navigation. Do not queue outdated visual states, wait for choreography before accepting input or strand focus. Cancel motion separately from a real request: cancelling an animation must not imply that data work was cancelled. Prefer bounded transform/opacity effects where suitable; do not rewrite package layout transitions for a blanket property rule. Reduced motion removes spatial effects while retaining state feedback; gesture actions need ordinary keyboard/button alternatives.

## Choose opportunities before recipes

For each proposed effect identify the real state seam, purpose, expected repetition and cost. Useful purposes include immediate feedback, spatial continuity, state explanation or a relevant infrequent expressive moment. Reading values, navigating lists and repeated keyboard work should stay stable and immediate. Marketing permits more expression than a dense operational screen, without moving the data a visitor is trying to use. No animation quota; zero additional effects can be the right result. Ordinary restrained image feedback and existing reveal requirements still apply.

Start with the installed component's behavior and timing. For an owned local state transition, CSS transitions can retarget smoothly; preserve existing enter/leave lifecycles rather than overriding them with a fixed timeline. Use supported native animation APIs only for a proven local need; no new motion library, gesture engine, observer, hand-written scroll loop or FLIP DOM-reparenting system. Keep trigger-linked surfaces spatially coherent and exits prompt. Don't animate from scale zero, bounce every action, or delay focus/input until an animation ends. A keyboard trigger is not a blanket prohibition on existing accessible component motion; avoid extra choreography on frequent actions.

Existing timing ranges are contextual, not conflicting hard caps. Ordinary feedback should settle promptly, often within 150–300ms; larger existing drawers may need longer. Reuse established easing tokens, choose a prompt response without a sluggish initial wait and evaluate the complete motion at ordinary speed. Do not force external exact curves, press scale 0.96, mandatory stagger/blur or fades under reduced motion. Immediate static feedback is valid. Theme switching should not launch a page-wide color smear; verify the current store/shell behavior before proposing an upstream change, never force synchronous layout/global transition suppression from a page.

## Diagnose and measure motion cost

Prefer small bounded transform/opacity changes, but do not claim a property or CSS/WAAPI driver guarantees compositing or 60fps. Browser, layers, area, device and concurrent work matter. Layout-dependent disclosure can legitimately change height; reuse the package implementation and profile it. Scaling a panel is not equivalent to real expansion: stretched glyphs, wrong flow, click geometry or obscured content are regressions. Grid-track and intrinsic-size transitions still involve layout; they are not compositor-only tricks.

When motion stutters, identify the cause before changing it: repeated layout/paint, a busy main thread, per-frame Vue updates, inherited animated variables invalidating many descendants, too many moving nodes, oversized layers or filters. Inspect during hydration/navigation/loading and with realistic content. Don't rewrite reactive state or bypass component ownership to achieve a cosmetic optimization. For legitimate measurements batch geometry reads before writes; don't alternate them across nodes or add measurements to ordinary render paths.

Keep gradients, shadows and local edge filters static when possible. If a necessary hover shadow repaints a large area, a single application-owned pointer-transparent pseudo-layer with static shadow and opacity may be cheaper; verify actual cost and focus/stacking. Do not mechanically replace shadows with drop-shadow, duplicate large media or allocate layers everywhere. Never animate blur radius, rely on translateZ(0) as a cure, or leave permanent will-change. A measured temporary promotion must be scoped and removed when idle.

For material motion changes or reported jank, record representative browser Performance traces and compare before/after: long tasks, forced layout, paint area, dropped frames and layer cost. At 60Hz the total frame interval is about 16.7ms; at 120Hz about 8.3ms, not all available to application code. A screenshot or lack of layout events is not a frame-rate measurement. Desktop CPU throttling does not reproduce a weak mobile GPU or memory budget; distinguish simulated from real-device checks. If profiling is unavailable, report that limitation and keep effects cheap rather than claiming verified 60/120fps.

## Soft edges

Translucency is optional functional separation, never an Apple-style requirement. Distinguish a blocking modal from a parallel panel using existing semantics and focus behavior; visual materials alone don't make a surface modal. Keep a readable solid fallback, honor supported reduced-transparency/contrast preferences, and don't stack translucent panels or animate blur to create hierarchy.

Use a local fade/mask where it helps an image merge into its intended surface, rather than applying blur to the entire page. Keep image detail sharp. Never turn this into a milky white veil, foggy full-section gradient or default cream/pastel background; fade toward the actual chosen surface token. Prefer existing Grid/view background and mask APIs. If a real soft edge is needed, a single shallow decorative band with a small static backdrop blur and a gradual alpha mask can suffice. Keep it bounded to the image boundary, behind content, `aria-hidden` and pointer-transparent. Do not duplicate large images or copy a reference's multilayer blur stack by habit.

Essential text, links, inputs, focus rings and controls must remain outside the obscured area. Do not animate blur radius, apply full-screen fixed backdrop filters or leave permanent `will-change`. Check compositing cost on mobile. Provide an ordinary surface fade when filters/masks are unavailable; clear decoration for forced colors or reduced transparency where supported. A readable static image without blur is a valid fallback.

## Scroll-driven letter color

Use for one short editorial statement, never the main body or a whole page of individually animated letters. Inspect the package for a suitable API first. If missing, a local native CSS enhancement may color a bounded number of deterministic SSR-rendered spans; it must not add another JavaScript observer, scroll listener, frame loop, dependency or polyfill.

The initial gray must already be readable against the real surface (normally at least 4.5:1). The effect changes emphasis, not visibility. Keep the sentence as one meaningful, selectable accessible text. Prefer a single visible character sequence; a heading can expose the complete accessible sentence through its supported accessible name while decorative character spans are hidden from assistive technology. Verify the heading name in the accessibility tree. If using a decorative duplicate for precise letter coloring, mark only that duplicate `aria-hidden`, pointer-transparent and unselectable; retain the single readable base sentence. Verify exact font, leading, baseline and line wrapping: two slightly offset text copies visibly fail, even when computed animation progresses. Do not split natural word wrapping with inline-block characters, duplicate screen-reader announcements or mutate the DOM after hydration. Locale changes must update the sentence and deterministic indices together.

Enhance only when both `animation-timeline` and `animation-range` are supported, with `prefers-reduced-motion: no-preference`. Put timeline/range declarations after any animation shorthand, which resets them. Use a local named view timeline and short bounded color progression, with no geometry changes. Inspect its actual scroll ancestor: background Grid sections may clip overflow and become a non-scrolling timeline container. Define the timeline on the appropriate section root when its own scroll ancestor is the page; do not remove package overflow or add a scroll listener to conceal the cause. Unsupported browsers, no JavaScript and reduced motion retain a complete sentence in its final readable color. Test the actual computed first/middle/last-letter states before, during and after scroll; declaration support alone is not proof the timing works.

Color animation can repaint: bound the statement and affected area, and omit the effect if it causes measurable jank. No per-word entrance queues or simultaneous animation of large backgrounds. Static quality takes precedence over matching a moving reference.

## Requested animated demonstrations and exports

Read this section only when the user requests an animated product demonstration or a motion/video/GIF artifact. A live website, interactive product and exported showcase have different contracts; ordinary site creation does not authorize a loop in every visual, an empty first frame or exports. Hero content stays immediately readable under the root rule.

Write the demonstrated relationship in one sentence, then choose only the motion that explains it. A live request's data and progress stay truthful; illustrative scenarios must be identified and must not impersonate working controls. Maintain readable semantic web text, installed UI/Grid/media behavior and the real static resting state. A flat screenshot does not supply hidden layers/content or permission to trace proprietary assets; request needed originals or disclose any permitted approximation. Do not create a fixed absolute-positioned replica as the website layout or bake its text into raster layers.

For an explicitly requested loop, inspect start/middle/end, the resting frame and the loop seam for clipping, jumps or ghosting. Pause nonessential activity when offscreen/hidden through existing capabilities, retain a complete reduced-motion/no-JS/poster path and necessary pause controls. No extra observer/clock/animation stack, automatic sound/haptics, autoplay story on every card or compulsory format/size. Export only requested deliverables with available tools, verify their actual dimensions/weight/playback and distinguish captured frames from runtime frame-rate evidence. Pixel-difference metrics may help a faithful requested reconstruction, not establish creative quality or accessibility.

## Feedback and acceptance

For image-led project/product/card previews, specify one visible, restrained hover treatment. A crop scale around 1.02–1.04 over roughly 200–350ms is a starting range, not a mandatory effect: keep the existing frame dimensions, subject/focal point and sharpness. A restrained tone/overlay change or real caption emphasis may suit the subject better. Do not routinely desaturate-to-color, blur-to-sharp or lift every card as a fixed recipe. No 3D tilt without explicit request.

Use existing APIs and site-owned selectors. Gate pointer-driven transforms with `@media (hover: hover) and (pointer: fine)`; preserve normal touch behavior without sticky hover states. Under reduced motion, remove scale/movement and keep useful static color/border/underline feedback. Linked previews also need keyboard focus feedback (`:focus-visible` / `:focus-within` as appropriate), native focus and accessible names. Do not make static images focusable just to run decoration.

Non-linked media can have a quiet decorative image response, but must not acquire a pointer cursor, fake open action or button-like lift. Never hide essential captions/actions until hover. No layout shifts, expanding frames, `transition-all`, animated blur, JavaScript mouse tracking, permanent `will-change` or added dependencies for this. Do not reach into package internals; use supported media classes/slots or existing application-owned presentation.

Before delivery, test rapid reversal/navigation during transitions, pending-to-error recovery, genuine progress and reduced motion. Then actually hover representative previews and focus real links in both themes. Compare readable before/after captures and computed states: visible response, crisp crop, stable layout, no clipping of focus/text and no misleading action. Check coarse-pointer/touch and reduced motion separately; a declared transition alone does not prove the effect works.

Inspect wide/narrow screenshots and actual scrolling in both themes and both built outputs. Verify reduced motion, static/no-JS reading, selection, accessible names, focus, first-frame media and palette overrides. Check that masked edges never obscure actions and that mobile card offsets return to useful flow. Compare motion disabled: the page must remain understandable and composed. Record the reused API, proven presentation gap, fallback and checks in the site's design/validation notes.
