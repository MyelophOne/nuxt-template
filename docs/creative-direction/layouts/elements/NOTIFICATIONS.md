# Notifications through the installed vue-sonner

Read when a task needs toasts or async result feedback. This layer uses **vue-sonner**, not React `sonner`. Inspect the consumer's installed version/module/types before using methods/options. No second notification library, toast wrapper system, copied stack/swipe implementation or page-level Toaster.

Current source evidence (vue-sonner 2.0.9): `nuxt.config.ts` enables `vue-sonner/nuxt` with `css: false`; inherited `app/app.vue` mounts the shared client Toaster with `currentTheme`, responsive position and `UiSonnerStyle`. The style component loads `vue-sonner/style.css`. Reuse these owners; do not copy React setup, `next-themes`, React hooks, CSS paths or configuration into a site. Test after theme/position changes rather than assuming a pending toast survives the shell's keyed remount.

The installed Nuxt module registers the client `Toaster` and provides `$toast` through a client plugin; it does not register a standalone `toast` auto-import. Verify generated declarations in the actual app. Prefer the supported injected client API obtained in setup when suitable; never access it during SSR or from a Nitro handler. A direct external import is allowed only when it is not auto-imported in that context and actually needed. Do not add a fake `useToast` composable. Existing source imports are not a reason to duplicate providers.

Use inline status for field-specific/critical problems; a toast suits a brief nonblocking result. Keep terms complete and localized with useMultiLang. Success follows the real operation; failures explain recovery without exposing secrets. Pending may use the installed loading/promise API; verify its return type, settlement and error behavior rather than assuming React parity. Update the same operation by its supported ID instead of stacking loading/success duplicates. Dismissing a toast does not cancel a request, and an Undo action requires a real reversible operation.

Don't announce every keystroke or emit both a watcher toast and an event-handler toast. Deduplicate repeated failures where appropriate. Essential errors/actions need a persistent inline/history alternative or an accessible dismissal/persistence policy; no important information available only before a short timeout. Keep forms and focus usable; notification appearance must not steal focus.

Style through supported Vue options/classes/variables and the owning layer, using semantic text/surface/status roles. React `classNames`, headless JSX and `!important` escalation are not portable recipes; this project's build strips important declarations. Do not replace the shell or inject global style/DOM patches to conceal a styling gap. Preserve meaningful status text/icons, readable actions, forced-colors boundaries and focus.

Verify one delivered notification per operation; loading → success/error; repeated activation; dismiss; real action; long localized text; screen-reader announcements without duplicates; keyboard access; both themes; mobile safe areas and coexistence with menus/dialogs/consent. Check stylesheet/CSP/chunk loading on SSR and generated outputs. Source inspection is not proof these interactions passed.
