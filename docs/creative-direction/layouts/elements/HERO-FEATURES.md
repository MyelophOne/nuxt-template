# Hero / proof / feature compositions

Read only for these regions. Keep explicit composition; recommendations are relationships, not a copied hero component.

| Content job | Starting relationship |
| --- | --- |
| Explain a simple offer | Clear proposition, concise support, dominant action and a subject-specific focal point |
| Let work/place/product lead | Large purposeful image scene, readable copy in negative space, useful caption/action |
| Explain a difficult capability | Relevant readable input/output or detail beside/after concise explanation |
| Introduce a ready-to-start task | Necessary choice/form/action plus conditions, quieter context |

Use the package's full-width GridStack/media APIs for large hero images; constrain copy only. Native foreground UI can have its own bounded stage, but don't disguise a large image as a card to evade the full-bleed default. No default carousel, autoplay scenario rotation, 3D or staging preloader.

A feature group may combine a dominant demonstration with related explanation, an open list or a user-selected scenario using an actual existing tabs/accordion contract. Every control must affect its described content; selected state/input/output must agree. Never fabricate dashboards/charts to fill a service page. Keep hero/LCP immediate; use relevant below-fold reveals/hover through existing mechanisms.

Mobile chooses a meaningful crop/detail and readable order; don't shrink entire screenshots into noise or cover the subject with text. Inspect intermediate widths, nested heading type, action contrast and actual responsive image resolution.

Verify the offer, task and next action are understood before reading the whole page, and that removing motion doesn't destroy the composition.
