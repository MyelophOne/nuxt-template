# Forms / selection / action flows

Read for actual data entry, checkout, settings or confirmation. Preserve the requested flow and use installed input/textarea/selection/upload/button/feedback contracts; do not recreate native/ARIA behavior beside available primitives.

Default relationship: explain the task and necessary conditions → logically grouped fields → review/total when needed → clear action → true result/recovery. A contextual summary can sit beside a long form on desktop; mobile brings important conditions before commitment and keeps the next action reachable. No gratuitous multi-step wizard for a short task.

Use persistent labels, examples as placeholders, clear required/optional treatment and requirements before submission. Verify name/type/autocomplete/required/inputmode and associations reach the actual control; attributes on a wrapper are not proof. If forwarding is missing, report the precise upstream gap rather than replacing the package input. Don't block paste or add unrelated autofocus/validation machinery.

Validation explains correction near the relevant field. Preserve entered values, give useful focus/announced feedback through existing semantics, and distinguish first-use/no-results/permission/failure states. Keep the action available according to its real contract; prevent duplicate pending mutations without disabling unrelated work. Use honest indeterminate status unless actual progress exists.

Destructive changes need a deliberate recoverable/confirmed path according to the operation, with named consequence; no fake undo or assumed cancellation. A request sent is not a confirmed booking/payment/saved result. No invented contacts, privacy promises or success states.

Keep complete translatable messages in the package's i18n/ready-page arrangement. Test native input attributes, keyboard, touch, long values/translations, zoom, rapid submit, pending-to-error recovery and the real endpoint/return path in both outputs. A generated site must use a compatible actual backend if required.
