# Cards / plans / metrics / comparisons

Read only for the relevant grouping, not every page. Use existing UiCard/Heading and source-verified table/selection contracts. Page columns remain Grid.

- **Comparable choices/plans:** shared decision fields and comparable emphasis; align meaningful price/action areas where it aids comparison. No arbitrary offsets that make matching hard.
- **Editorial work:** dominant/companion scale, purposeful aspect ratios and top offsets can express priority; clear mobile offsets when they create dead space.
- **Feature/service unit:** heading, useful explanation and actual output/example; icons are optional, not the card's entire evidence.
- **Metric/table:** the relevant value/relationship leads; show actual labels, units, period/source/conditions. No obligatory KPI boxes, gauges or invented trends.

Related information should group by proximity before adding boxes/dividers; UiCard remains appropriate when a distinct unit helps scanning. Coordinate insets, edges, radii and elevation through tokens; not every nested element gets its own surface/shadow.

Use tabular numerals for comparable/dynamically changing values where helpful, with locale-aware formatting of actual data. Do not infer status from color alone or make labels illegible. Preserve table header/value relationships; local horizontal scrolling can serve narrow comparisons better than losing fields.

A linked card must have a real destination and proper focus. No nested controls inside a whole-card link. Static cards have no fake open affordance; relevant image previews still get restrained decorative hover without implying a click result.

Verify long/empty values, real result counts, both themes, touch/keyboard and narrow reading. Truthful context and grouping matter more than equal heights or fashionable bento geometry.
