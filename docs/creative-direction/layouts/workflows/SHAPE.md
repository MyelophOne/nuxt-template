# Shape an unresolved feature/flow

Read only for material ambiguity in a new surface/flow or an explicit planning request. This is not a mandatory interview before every task and does not activate an external skill.

Reuse known context, real materials and established visual direction. Identify the visitor, their actual verb, the evidence/data needed and what counts as success. Ask one concise group of material unanswered questions; do not request CSS values, repeat settled facts or seek confirmation for routine authorized choices. Continue useful independent work while a required answer is pending.

Produce the smallest useful brief, normally 3–5 bullets: job/audience; intended outcome/evidence; scope/preserved boundaries; important states/content ranges; unresolved dependency/decision. A multi-step flow may need a compact entry → choice → action → result/recovery map. Record unsupported integrations/assets rather than inventing them.

If the user requested only a brief, deliver it. If implementation is authorized and the material decisions are settled, proceed through the shared design/build workflow; do not stop because the source skill prescribes a confirmation ceremony. Explicit user layout/palette and Nuxt package constraints govern every choice.

Verify that a builder can implement the real task without guessing its essential facts, states or backend boundary. Do not turn the brief into a long design manifesto or impose an unrequested scope expansion.
