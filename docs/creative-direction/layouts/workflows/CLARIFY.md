# Clarify interface language

Read for confusing labels/messages, inconsistent terminology or localization copy, not every layout task. Inspect the whole relevant flow and preserve factual meaning, audience vocabulary and brand voice.

For each state identify the fact needed now, next action and supporting consequence. Name actions by their actual outcome; use consistent nouns/verbs through controls, pending and result. Remove repeated heading/helper/confirmation text that adds no information. Distinguish first use, no matches, permission failure and system failure rather than calling all of them empty.

Forms need persistent labels; placeholders provide examples. Explain format/eligibility before submission where relevant. Errors identify what failed and how to recover without blame or invented causes. Significant destructive/privacy/payment consequences must remain accurate; ask about an ambiguous fact or legal meaning rather than rewriting it casually.

Use complete translatable messages and structured dynamic values through the existing multi18n/ready-page contracts, not concatenated fragments or a new localization system. Keep visible and accessible names consistent. Allow long translations and actual pluralization without clipping.

Verify in context at narrow widths and zoom, including real errors/empty states, dynamic values and announced changes. A concise message still retains meaning, consequence and recovery. Do not add jokes, filler reassurance or new backend promises.
