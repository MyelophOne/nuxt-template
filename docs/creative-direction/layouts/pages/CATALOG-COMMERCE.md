# Catalogue / library / commerce

Read for a real collection or product decision; choose the relevant subsection. A library does not automatically need cart/checkout.

## Collection default

Category/context → useful search/filter/sort when in scope → real items at scannable density. Desktop may use a narrow filter region beside the main listing; mobile prioritizes results with compact accessible filter entry. No obligatory large marketing hero or two sidebars before results.

Cards expose useful image/title/category/price or appropriate metadata. Counts, selected filters, order and empty states must describe the same actual data. Preserve useful selection/query on returning from details. Route/query persistence is deliberate through existing Nuxt navigation, not a second router; same-page section links still obey the no-hash rule.

UiSiteSearch is not automatically a collection-filter API. Inspect suitable contracts; domain selection may compose existing primitives without copying their behavior or installing a new search stack.

## Product-detail default

Meaningful gallery/media beside actual name, price/availability/specifications, required choices and primary action; on mobile use gallery → essentials → choices/action. Put sizing/delivery/returns/limitations near the decision when relevant and confirmed. No fake ratings, discounts, stock urgency or purchase success.

Reuse installed gallery/lightbox, cards, controls and real cart domain when configured; no new basket/store. Checkout exists only when requested, then consult the forms profile. Keep comparative table labels on phones: contained scrolling is valid where columns matter; unlabelled cards or hidden critical values are not.

Verify browse/refine/open/return, accurate counts/choices, long names, meaningful image hover and the true requested cart/action outcome. Root catalogue/product depth, metadata, theme and dual-mode requirements apply.
